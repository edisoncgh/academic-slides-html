# Academic Slides HTML Skill

学术汇报设计稿生成工具——让 LLM 帮你理清"这篇论文该怎么讲"。

## 核心理念

### 问题：为什么 Agent 生成的 PPT 总是不好用？

现阶段指望 Agent 一步到位生成能用的 PPT 是不现实的。这不是因为 Agent 不够聪明，而是：

1. **Office 操作受限**：Agent 对 PowerPoint 的操控能力有限
2. **格式转换损耗**：PDF/docx 中的图表、公式在提取过程中丢失
3. **图片处理困难**：生成的 PPT 往往是纯文字的，缺乏关键图表

### 解题思路：脱离 Office 的束缚

主流 LLM 在训练时接触了海量 HTML+CSS 代码，生成网页样式的能力远超操控 Office 的能力。

**HTML 和Markdown一样，是 LLM 广泛接受的原生输出格式。**

如果我们把目标从"生成 PPT"转变为"生成 HTML 格式的设计稿"，Agent 就能充分发挥其优势：
- 精准控制布局和样式
- 图片用 base64 内联，自包含无依赖
- 双击即可在浏览器中查看

### 重新定义交付物

这个 skill 的产出不是"成品 PPT"，而是**设计稿**：

> 帮助用户看到产出后能感觉到："噢！我这篇论文应该是这样汇报的，我明白了。"

核心价值在于：
- **构造逻辑链条**：论文内容如何组织成汇报叙事
- **把控汇报节奏**：每部分用多少 slide、讲多深
- **刻画内容规划**：每页 slide 该展示什么、为什么

视觉设计是次要的，叙事设计才是重点。

## 产物说明

| 产物 | 格式 | 用途 |
|------|------|------|
| `{topic}.html` | 单 HTML 文件 | 视觉设计稿，浏览器打开即可查看 |
| `{topic}-script.md` | Markdown | 演讲草稿，指导每页 slide 该怎么讲 |

**HTML 文件特点：**
- 完全自包含，单文件无外部依赖
- CSS scroll-snap 实现 slide 切换
- 16:9 比例，模拟真实 PPT 体验
- 所有图片 base64 内联
- 系统字体（中文宋体/黑体，英文 Times New Roman）
- 纯静态，无交互，专注内容展示

## 支持的汇报类型

| 类型 | 适用场景 | 默认结构 |
|------|----------|----------|
| 论文汇报（自己的） | 会议演讲、论文答辩 | 动机→方法→实验→结论 |
| 论文汇报（别人的） | 组会分享、文献精读 | 问题→方法→亮点→启发 |
| 组会进展汇报 | 实验室组会 | 背景→各工作→下一步 |
| 综述/文献调研 | 领域调研汇报 | 主题→各方案→对比→总结 |

## 输入格式

**强烈推荐 Markdown。**

如果只有 PDF 或 docx 文件，建议先使用以下工具转换：
- [MarkItDown](https://github.com/microsoft/markitdown)
- OfficeCLI
- 其他文档转换工具

当然，也可以交给你的Agent自己来处理这一步。

## 工作流程

```
1. 收集信息（询问汇报类型、时长、输入源）
   ↓
2. 分析内容（识别结构、发现图表）
   ↓
3. 规划结构（根据类型和时长确定 slide 架构）
   ↓
4. 处理图片（提取、分配、base64 编码）
   ↓
5. 生成 HTML（单文件设计稿）
   ↓
6. 生成演讲草稿（Markdown 格式）
   ↓
7. 输出总结
```

## 解决"纯文字 PPT"问题

这是本 skill 的关键改进点。通过完整的图片处理流程：

1. **图片发现**：扫描文档，识别所有 Figure/Table
2. **图片提取**：从 PDF 中提取原始图片（PyMuPDF 等工具）
3. **图片分配**：根据叙事逻辑将图片映射到合适的 slide
4. **图片嵌入**：base64 编码内联进 HTML，自包含无丢失

## 与其他 skills 的区别

| 对比维度 | paper-slide-deck / baoyu-slide-deck | academic-slides-html |
|----------|-------------------------------------|----------------------|
| 产出格式 | PNG 图片 → PPTX/PDF | HTML + Markdown |
| 核心价值 | 视觉风格、图片生成 | 叙事设计、逻辑结构 |
| 交付定位 | 成品幻灯片 | 设计稿/灵感参考 |
| 技术实现 | AI 图片生成（Gemini） | 原生 HTML/CSS |
| 图片处理 | 提取原图 + 模板套用 | base64 内联，完全自包含 |
| 交互性 | 静态图片 | 浏览器查看，scroll-snap |

## 设计哲学

1. **图表为主，文字为辅**：学术汇报的灵魂是图表，不是大段文字
2. **固定风格，专注叙事**：不追求视觉多样性，专注于"怎么讲好这个故事"
3. **设计稿而非成品**：帮用户获得灵感，而非替代用户的创造力
4. **自包含交付**：单 HTML 文件，打开即用，传递无损

## 使用场景

- **会议演讲**：准备 conference talk 的 slide 设计方案
- **论文答辩**：规划答辩汇报的逻辑和节奏
- **组会汇报**：组织近期工作或文献阅读的汇报结构
- **自我梳理**：通过生成 slide 理清论文的讲述逻辑
